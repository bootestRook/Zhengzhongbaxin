# 正中靶心 · 战斗复刻初版

基于已有拆解研究和当前热更资源，在 Godot 4.7.1 中重新实现的离线竖屏守城 Demo。当前开放第 1 至 5 关，包含英雄招募、自动战斗、局内强化、守护雕像、宝箱、职业计时复活与胜负结算。局外养成采用统一固定输入。

这是可运行的初版；默认解锁勇者、火焰术士、德鲁伊、寒冰射手、闪电刺客五名英雄及各自词条，其他英雄和词条局内暂不可选。局外英雄页展示全部英雄，未解锁卡片置灰。数据已接入不等于每个技能分支都已与原客户端逐帧一致。范围、验证和已知差异见 [初版说明](docs/DEFENSE_DEMO.md)。战狂因热更缺少技能树，不进入可选范围。

召唤站位、战斗 AI、动作关键帧、波次、弹体与死亡触发的最新对照见 [战斗规则验收](docs/DEFENSE_COMBAT_FIDELITY.md)。

暂停退出及胜负结算按实机显示武器横幅、进度、五名英雄统计与MVP、奖励，并分阶段播放动效；英雄卡 i 可查看本局属性，确认返回主界面。当前普通奖励配置为空时显示“未获得奖励”；最好进度仅在当前运行期间保留。依据和验证边界见 [结算实机记录](validation/defense/result_reference_findings.md)。

当前五名英雄各有一项初始技能：勇者圣盾10秒、火焰术士火球术6秒、德鲁伊荆棘护甲15秒、寒冰射手多重射击4秒、闪电刺客刺杀8秒。勇者和刺客普攻完整动作结束后等待1秒，其余等待2秒。元素、种族、技能效果与验证边界见 [新版五英雄](docs/DEFENSE_HERO_ROSTER.md)。勇者已替换为[圣盾词条库](docs/DEFENSE_WARRIOR_TERMS.md)，初始减伤50%、持续4秒，坚守阵线内置冷却0.5秒。火焰术士已替换为[火球术与炎爆术词条库](docs/DEFENSE_FIRE_TERMS.md)，仅结算100%基础范围爆炸，支持5°散射、引燃、余烬、蓄力护盾与穿透爆炸。德鲁伊已替换为[荆棘护甲词条库](docs/DEFENSE_DRUID_TERMS.md)，包含独立额外护盾、受击反伤、缠根、花灵与完整前置树。寒冰射手已替换为[多重射击与星辰之箭词条库](docs/DEFENSE_ICE_TERMS.md)，400随招募获得，支持穿透、齐射、冰冷、击退、集中与寒冰箭雨；这些词条仅作用多重射击及其升级、派生效果，普攻不触发也不继承。闪电刺客已替换为[刺杀词条库](docs/DEFENSE_ASSASSIN_TERMS.md)，基础300%电伤，支持连击、麻痹、烟幕、刀扇、追猎、感电、普通怪物斩杀及精英/首领最终三倍伤害。较早原始规则的逐英雄复核见 [全英雄技能复核](docs/DEFENSE_HERO_SKILL_AUDIT.md)。

当前雷电配置、逐英雄索敌与移动边界、全部怪物数值及小怪血条的再次核对见 [再次复核报告](validation/defense/battle_reaudit/复核报告.md)。

击杀精英或首领必定自动触发转盘并暂停游戏，普通怪不触发；精英和首领的数量、波次及触发时间读取刷怪表，全部实际特殊单位击败并关闭奖励后结算胜利。先按50∶30∶15∶5的权重决定获得1至4项，再从已招募英雄的剩余合法词条中抽取；规则及交互见 [自动宝箱奖励](docs/DEFENSE_CHEST_FIDELITY.md)。

普通开局和重试采用新的每局种子，英雄刷新排除上一组、强化按英雄权重及对应词条权重抽取；相同显式种子仍可复现。规则与验证见 [三选一抽取](docs/DEFENSE_CHOICE_RULES.md)。

## 当前体验规则

每局二十波、最高二十级；各波逐行读取确定的怪物 ID、数量、触发时间、批次间隔、分布方式和逐行倍率。波次类型为空为普通怪，2 为精英，3 为首领。开局三选一招募第一名英雄；以后每次升级的每个卡位按25%招募、75%强化混抽，允许同轮0至3张招募卡。英雄上限五名，满编后只出强化；不保证固定等级满编。强化保留原英雄平衡权重；五名英雄按新版逐条权重，宝箱和指定英雄额外奖励只提供强化。雕像不攻击，局内不抽取雕像强化。战士、守护、刺客死亡后20秒复活；法师、射手、辅助10秒。从死亡瞬间按战斗时钟计时，复活不消耗雕像血量；近战和远程英雄在雕像正前方出生或复活，途中优先攻击范围内的敌人，攻击或施法动作完整结束后，利用冷却空档继续向阵位行走；即使范围内仍有敌人也不原地等待，普攻或技能就绪时优先出手。

本项目体验规则及验证见 [体验优化](docs/DEFENSE_EXPERIENCE.md)。较早的原客户端对照保留为历史证据，当前玩法以 rules.json 和本页为准。

前排按用户红框采用固定追击上边界Y=480（720×1440窗口约在画面Y=287），步行追击不越界，边界外处于实际普攻或技能射程内的敌人仍可被攻击。刺杀及追猎可以瞬移到框外目标处，完成当前动作后逐步走回框内。取消按各自阵位向前100及横向300的接敌限制。前排优先回防后方漏怪，近身接战时冷却站稳，无目标时步行回位。远程普攻和技能分别按实际射程索敌，删除Y=850交战区域过滤，普通敌人超出普攻范围时保持后排站位，保留必要的首领收尾。入场只攻击沿途实际能打到的敌人，保留冷却归位及完整攻击、施法动作。

没有目标的普通怪在警戒线Y=550前竖直下行，保持出生横坐标，仅在接触时局部避让；进入接敌区后按阻挡容量寻找英雄，未被阻挡时直接朝雕像推进。追击寻路把拥挤计入实际路径成本，脚部接触采用侧向绕行且不额外增速，不推动站稳的单位。嘲讽、首领索敌、攻击框和英雄移动边界继续独立生效。

每局刷新共2次，开局招募、升级混选及额外强化共用次数；升级或进入下一轮不补充，开始新局或重试恢复2次。宝箱转盘不可刷新，也不消耗次数。

## 运行

日常数值配置使用 `data/source/defense_tables/` 下8个独立中文XLSX，包含正式宝石表；刷怪配置直接逐行填写怪物 ID，不使用怪物池子。修改保存后双击根目录 `导表.bat`，成功后重新启动游戏。关卡系数、逐行刷怪、宝石及其他表格的填写规则见 [配置表说明](docs/CONFIG_TABLES.md)。局外英雄升级仍未实现，英雄表只提供当前实际生效的初始属性与身份设定。

双击根目录 `启动游戏.cmd`。修改源表或图资源后，双击 `更新并启动.cmd`。需要 Python 3.10+ 和 Godot 4.7.1；本机环境已检查。也可在 Godot 打开 `project.godot` 后按 F5。

```powershell
python tools/project.py doctor
python tools/project.py run
```

Godot 不在 PATH 时设置 `GODOT_BIN`，或命令行增加 `--godot <可执行文件>`。默认桌面窗口 720×1440，逻辑画布 960×1920，保持纵横比。

主页底部“英雄”切换至英雄展示页，顶部玩家资料与资源、底部导航保持显示；“战斗”或 Esc 返回选关主页，点击关卡名称仍可选关。点击已解锁英雄切换上方角色，待机2秒、普攻一次、待机2秒、技能一次循环播放；未解锁卡片点击提示“还未解锁”。卡片显示职业、头像、Lv:1、碎片进度、名称和种族，不含九宫格。碎片暂显示0/14，尚未接入获取与升级；浏览不改变局内招募和战斗状态。实机验证见 [英雄页验收](validation/defense/hero_page/验收.md)。

选择关卡后点击开始挑战；点击三选一卡片的画像、名称或其他普通区域招募英雄、选择强化。招募卡正文仅显示招募英雄名；强化卡直接展示词条名和原始说明，长说明可在卡内滚动。招募卡的种族和职业以小字显示。卡片右上角 i 打开顶部属性面板，下方刷新按钮重新抽选本轮候选。强化卡的 i 显示所属英雄的本局属性、已学技能及输出/治疗/承伤，箭头可展开更多属性；点击空白处或 Esc 关闭。宝箱奖励自动弹出并暂停战斗，转盘中央显示精英掉落或首领掉落，格子仅显示填充图标；顶部数量滚动后依次转动、减速并揭晓词条原文；点击跳过全部动画显示结果，再次点击关闭并继续战斗。长说明可滚动阅读，拖动不视为点击。多个奖励依次处理。点击下方英雄头像打开“已选词条”二级面板，显示该英雄实际已获得的强化词条（排除初始技能），可在右侧切换已入队英雄；同一词条合并一行，超过一次时在名称行右侧显示X数量（如X2），说明保持表格原文，长列表支持上下拖动、触摸滑动和滚轮滚动。查看、切换和关闭均不主动暂停；点击面板外侧空白或Esc可关闭面板；短按头像下面的圆形技能图标显示对应技能描述；战斗中按住约0.4秒显示以对应英雄为中心的施放距离预览，淡红透明填充、红色流动虚线，松开或拖出图标即隐藏。范围跟随英雄并读取当前技能状态，效果范围强化不改变施放距离；圈内目标仍须满足目标类型、冷却、控制和动作条件。查看期间战斗继续进行。描述气泡可点击同一图标、纸面、空白处或 Esc 关闭。左上暂停及倍速。暂停页可查看本关画像与首领说明、切换伤害显示、继续或退出；左侧柱状图开关贡献度，怪物图标开关本关怪物列表，三选一右侧可查看宝石属性。Esc 可暂停、继续或关闭资料窗口。

主页底部“雕像”切换至装备与宝石页，共享玩家资料、资源和底部导航。默认穿戴六部位装备，每个部位另有一件同款备用装。正式宝石表保存在 `data/source/defense_tables/08_宝石.xlsx`，每个定义默认生成两份库存实例；七档品质保留各自形状及灰、绿、蓝、紫、橙、红、彩配色。装备下方五个孔位按镶嵌顺序显示宝石品质颜色，至尊显示彩色，空槽保留空心样式；镶嵌、替换和卸下时同步更新。背包按部位与正式宝石定义堆叠，宝石列表按品质由高到低显示，同品质保持稳定顺序；同一部位不能同时镶嵌同名效果，高品质可以替换低品质，同品质和低品质会提示原因且不消耗物品。宝石进入战斗后作用于英雄属性、技能、伤害和雕像效果，攻速与攻击范围暂缓；天罚按雕像生命损失阈值触发300范围昏迷。验证入口为 `tests/test_defense_gems.gd` 与 `validation/defense/statue_page/verify.gd`。

## 开发与检查

战斗测试场：双击 `启动战斗测试场.cmd`，复用当前战斗场景进行召唤/清怪、词条与属性编辑、不死靶、真实击杀、单步观察和保存重放。人工面板与自动化调用同一控制层；入口和边界见 [战斗测试场](docs/BATTLE_LAB.md)。

修改前阅读 [测试方案](docs/TESTING_AND_RELEASE.md)。日常修改按影响范围做定向验证，通过后停止；全量检查用于明确的高风险变更、阶段验收或打包发布。以下生成命令按实际输入变化选择，不要求每次全部执行：

```powershell
python tools/project.py data
python tools/project.py graphs
python tools/project.py assets
```

`python tools/project.py check` 是完整工程检查，涵盖数据与引用、生成物漂移、资产台账、架构约束、Python 管线、Godot 领域及场景测试、运行烟测；准备输入与执行条件见测试方案。当前 `test` 也会执行大部分全量检查，不能当作快速入口。源数据冻结在 `data/source/defense/`，无需连接原服务器或依赖外部拆解目录即可运行。

| 位置 | 内容 |
|---|---|
| `src/features/defense/domain/` | 战斗状态、AI、技能、波次与数值规则 |
| `src/features/defense/presentation/` | 图集、角色动作、战场、界面和音效 |
| `scenes/main.tscn` | 主界面、HUD、选择、资料和结算的固定骨架 |
| `data/source/defense/` | 当前热更配置、中文文本、资源索引与来源 |
| `art_source/defense/` | 原始资源归档与指纹 |
| `assets/runtime/defense/` | 运行图集、字体和音频 |
| `validation/defense/` | 实机截图、测试和性能记录 |

技术约定：[架构](docs/ARCHITECTURE.md)、[本次 ADR](docs/adr/0002-defense-battle-demo.md)、[Godot API](docs/OFFICIAL_GODOT_DOCS.md)、[打包规范](docs/PACKAGING.md)。通用 Core、Ability Graph 与原脚手架测试继续保留，游戏规则只属于 defense Feature。

代码与第三方素材的范围见 [THIRD_PARTY.md](THIRD_PARTY.md)。当前交付为可编辑工程及启动入口，未进行平台导出或公开发行验收。
