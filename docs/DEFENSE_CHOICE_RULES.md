# 三选一随机与抽取规则

当前玩法已按用户批准的[体验优化](DEFENSE_EXPERIENCE.md)改为五人、二十波及职业复活，并按ADR-0010取消固定招募等级。原四人、三十波、雕像选项与旧复活公式属于历史参考。

英雄/品质权重和资格过滤最初依据客户端的普通战斗抽取流程独立重写。升级25%招募/75%强化混抽是用户新规则，不宣称复刻原客户端概率。此前观察及热更核对作为来源证据保留。

## 每局与重放

普通开始、重试均由 App 组合根产生新的系统随机种子，注入领域 Session。移除重启时固定日期种子和按运行次数递增的旧路径。显式种子用于测试和复现；同种子、同操作仍重现候选、刷新和战斗结果。原版由战斗开始链提供种子、局内使用种子驱动随机，因此不能将领域随机改为每次调用系统随机。

新局可以随机抽到与旧局相同的候选；不会为了避免偶然重复而修改概率。

## 候选与刷新

- 每局刷新总计2次，开局招募、普通升级混选及指定英雄额外强化共用。每次成功刷新扣1次；升级、确认选择及进入下一次额外强化不补充。用完后本局刷新按钮禁用，直接刷新请求也被拒绝，不消耗随机数、不替换候选。新局和重试恢复2次。暂停或非选择阶段不允许刷新；宝箱仍不可刷新且不扣次数。
- 初版已解锁英雄仅限勇者、火焰术士、德鲁伊、寒冰射手、闪电刺客，对应 `rules.json` 的 `unlocked_heroes=[1,2,4,13,17]`。其他英雄不进入招募池，其词条不进入升级、指定奖励及宝箱池；选卡确认和自动宝箱每次发奖时再次检查。英雄和技能资料仍保留，图鉴可查看。
- 开局三张英雄候选选择第一名；后续每次升级每卡位先按25%招募、75%强化决定类型，再从该类合法池取卡，允许同轮0至3张招募卡。没有固定招募波次、固定招募等级或补满保底，可能二十级仍未满编。满五人或没有未招募英雄时只出强化；某类没有合法候选时使用另一类，两类都空时继续战斗。
- 英雄从当前可用且未入队的集合逐张按招募权重抽取，当前勇者和其他英雄均为5000等权，取出后从本轮集合移除，最多三张。刷新优先排除上一组候选；不足三张时把仍可用的旧候选补回。新一轮英雄招募不继承上一轮的排除名单。
- 普通强化每张先按英雄权重决定所属英雄；当前五名英雄按各自新版词条库的逐条权重抽取词条。英雄初始权重各为 5；确认强化后该英雄减 1、最低 0，其余已入队英雄各加 1。当前品质权重为 0、2000、4000、3000、1000。每张排除本轮已经出现的词条。
- 所选英雄没有有权重的可用词条时，从全局合法池均匀取一项。指定英雄的额外强化从该英雄合法池抽取：当前五名英雄按逐条权重抽取。
- 招募和强化分别去重，相同数字的英雄ID和词条ID互不排斥。已入队英雄不重复招募，英雄死亡不腾出名额。刷新重新决定每张卡的类型；只查看卡片不会消耗随机数或应用候选。
- 前置条件、互斥条件、每词条次数上限及 `isNew` 组上限统一检查；`numTable` 模板不作为候选。冻结来源表的42种全队雕像词条已从运行目录剔除。
- 宝箱与强化共用 Choices 的资格与英雄权重，宝箱使用独立 `defense.loot` 流，先抽1至4项数量，再逐项抽取并应用；奖励动效只表现既定结果。详见[自动宝箱奖励](DEFENSE_CHEST_FIDELITY.md)。
- 指定英雄额外奖励和宝箱只出强化，不参与招募混抽。每张卡必有`kind=hero/upgrade`；卡面显示“招募/强化”，初始技能、候选资料、所属英雄当前属性及确认行为均按该张卡的类型处理。普通升级历史记录实际所选类型。

初版解锁范围为 Demo 的固定输入，决策见[ADR-0011](adr/0011-defense-initial-hero-roster.md)；未接入原账号的解锁、关卡禁用名单、装备定向召唤、调试固定英雄或广告系统。保留工程现有命名随机流和 RNG 算法；相同种子用于复现本工程，不声称与原客户端的全局随机序列逐项相同。

## 验证

当前专项：`test_defense_mixed_choices.gd`在10,000次抽取、30,000个卡位中记录7,518张招募（25.06%），0/1/2/3张招募分别出现4,195/4,241/1,415/149轮。验证无重复、资格/已拥有过滤、同种子重放、刷新、五人及死亡占位、空池、ID碰撞、宝箱和指定奖励。`test_defense_mixed_choice_ui.gd`通过真实鼠标验证混合卡片的描述、i资料、分别确认、双击去重及刷新；旧英雄/品质加权与资格回归继续执行。

原生证据见`validation/defense/mixed_recruitment/`：`mixed/recruit_skill/recruit_info/upgrade_info/result`各含960×1920、720×1440、540×1080三档截图，总览为`review_matrix.png`。全部来自种子6的真实合法对局；首个混合面板在局内2级、显示第4波，包含一张招募与两张强化。基础雕像生命3900，招募英雄5/4/7/9/11，二十级、二十波、三位首领、6次死亡，模拟时间279792毫秒，最终胜利。共击败265个非首领单位；二十波定义共269个槽位，不把槽位总数当作实际击杀数。没有增强属性或直接杀敌取得胜利。`capture.log`保存对局历史与鼠标结果；完整检查为`project_check.log`。不代表全部五十关或移动导出已验收。

以下为混抽前的历史验证，数值仅对应当时源快照：

`test_defense_choice_rules.gd` 验证种子输入、无放回候选、刷新排除与不足回填、英雄/品质权重、回退、指定英雄、前置/互斥/次数/分组资格。`test_defense_run_seed_ui.gd` 通过真实开始按钮输入验证多个全新实例及普通重试，并验证显式种子和输入不变性。

`validation/defense/choice_randomness_capture.log` 的专项 67 条断言通过，记录三个新实例的不同种子/候选及第一次刷新结果；四张 `choice_fresh_start_*.png`、`choice_fresh_refresh.png` 为实际渲染证据。完整工程检查见该目录的 `choice_randomness_check.log`。

历史检查快照通过 2856 条 Godot 断言、34 项 Python 管线测试及运行烟测，无 `ERROR`/`SCRIPT ERROR`。当时完整对局的明确种子 6 使用实际候选和合法刷新/选卡，完成 30 波并击败三位首领；相同种子与策略重放一致。旧“始终选第 0 张”的获胜假设不适用于新的概率分布，因此未通过更改战斗数值来维持旧测试结果。当前固定登场分类以 ADR-0025 为准：第8、14波精英，第20波首领。
