# 配置表与双击导表

八个独立 XLSX 位于 `data/source/defense_tables/`，均为中文表头。正式宝石表为 `08_宝石.xlsx`，每行定义一个宝石效果，允许部位由六个部位列中的 `√` 表示。保存表格后双击根目录 `导表.bat`。成功后重新启动工程中的游戏；已经导出的 EXE 需要重新导出才会包含新配置。

| 文件 | 主要编辑内容 |
|---|---|
| 01_英雄属性与局外成长.xlsx | 全部英雄的初始属性、当前五英雄身份与初始技能关联；局外成长尚未实现，文件内明确说明，没有虚构成长数据 |
| 02_英雄技能.xlsx | 完整描述、技能冷却、距离、伤害及能力参数、目标规则和共用被动；前五条为当前英雄初始技能 |
| 03_英雄词条.xlsx | 前47条为当前英雄词条；名称、说明、权重、次数及前置与强化明细；其后为锁定英雄与资料记录 |
| 04_Buff配置.xlsx | 状态属性、护盾、跳伤、控制与叠层；施加时长由引用它的技能或词条控制 |
| 05_怪物配置.xlsx | 怪物名称、怪物描述，以及怪物和召唤物基础生命、攻击、每级增量、移速、攻击速度、技能和特性 |
| 06_关卡配置.xlsx | 每关生命/攻击系数和生命/攻击成长额外等级（原“修正加级”） |
| 07_刷怪配置.xlsx | “关卡波次配置-1测试关卡”逐行维护关卡、波次类型、确定怪物 ID、数量、触发时间、批次间隔、单次刷新数量、分布方式、攻击/血量系数和血条数量 |

## 填写规则

- 保留工作表名与中文表头；允许调整列顺序、排序和插入合法数据行。不要修改 schema。
- 配置单元格只填实际值，不使用公式、外链或宏。编号以表中原有的文本或数字类型填写，不能随意改为显示名称。
- 空白表示未设置可选字段；`〈空文本〉` 表示明确的空字符串。零值与空白不同。
- 普通标量在主表；列表、前置、技能链及嵌套能力在对应明细表。按记录编号查找，参数名称辅助识别，参数键与路径确定对应字段。数组路径从0开始，层级用斜杠分隔。列表/对象行保留结构，值列留空；普通参数按“值类型”填写。
- schema 只保留原有空数组的结构信息，避免大量重复空行；需要为这些字段添加内容时，在明细表添加列表根行和成员行即可。
- 定义层沿用当前数据分工。基础、英雄覆盖、英雄新增负责构建同一套定义；表格内每个参数只有一个值，不存在回退到研究快照的缺失补全。
- 用途名称和英雄名称展示列为识别信息；实际英雄名称在“当前英雄设定”的名称列编辑。词条名称和说明分别编辑。
- 技能“完整描述”导出为技能的 `description`；前五条为现行初始技能完整说明。历史与派生记录没有独立原文时，明确标注并附关联词条原文及参数摘要。此列不反写数值，也不替换词条表说明，修改数值后需同步维护文案。
- 怪物“怪物名称”“怪物描述”直接导出为 `title` / `description`，替代旧文本编号入口。当前1至5关引用的怪物均有原文；未命名或无说明的历史空记录明确标注，不虚构技能效果。

## 刷怪与成长

刷怪表直接填写 `怪物ID`，不使用怪物池、权重或子表。`关卡ID` 1001 至 1005 编译为运行时关卡1至5。`波次类型` 为空为普通怪，2为精英，3为首领；数量、波次与特殊类型完全按行读取。

`触发时间`以秒填写；`刷新间隔`和`单次刷新数量`共同决定当前波次内的批次，实际批次数量不能超过该行剩余总数。`怪物数量波动系数`为0.1时，在数量的0.9至1.1区间采样并向上取整。`分布方式` 1为随机分布，4为中间分布。`血条系数`表示血条数量，1就是1管血。首次刷新数量字段不再使用。

初次导表保持现有数值，新增关卡攻击倍率和刷怪行倍率均为1，第2关生命倍率为0.51。现有算法先结算基础值与等级增量，再结算已有波次成长，最后相乘：

```text
生命 = 原有生命结算结果 × 关卡生命系数 × 本刷怪行局内生命系数
攻击 = 原有攻击结算结果 × 关卡攻击系数 × 本刷怪行局内攻击系数
```

攻击系数、血量系数直接使用刷怪行中的数值；公式结果必须先粘贴为数值。召唤物和英雄不受敌方倍率影响。

### 关卡成长与逐行系数

“生命/攻击成长额外等级”原名“修正加级”，表示怪物计算每级增量时额外按多少级成长，已合并原章节修正。生命成长段为 `基础生命＋每级生命增量×（关卡ID＋生命成长额外等级）`；之后继续结算累计波次生命成长、现有每3波成长以及两层倍率。攻击对应相同的等级加算，并额外累计刷怪表截至当前波的攻击成长加级。

例如基础生命100、每级增量20、第5关额外等级填3，这一段结果为 `100＋20×(5＋3)＝260`。填3不是生命加3，也不是乘3。

| 刷怪列 | 实际含义 |
|---|---|
| 波次类型 | 空白为普通怪，2为精英，3为首领。 |
| 触发时间 | 当前关卡时间，单位为秒。 |
| 刷新间隔 / 单次刷新数量 | 当前波次内的批次节奏和每批上限，最终批次受剩余数量限制。 |
| 分布方式 | 1为随机分布，4为中间分布。 |
| 血条系数 | 怪物血条数量，1表示1管血，不改变血量系数。 |

## 工具与验证

`导表.bat` 默认从上述目录读取8份文件，只在所有读取、类型、引用、范围和领域检查通过后，原子覆盖 `data/generated/defense_catalog.json`。错误提示包含文件、工作表、行与字段，部分跨表领域错误附记录ID。失败保留旧文件。

需要从另一个目录导入时：`导表.bat --tables-dir "D:\配置表"`。命令行可用 `python -X utf8 tools/defense_pipeline.py build`，只检查现有生成物可用 `python -X utf8 tools/defense_pipeline.py check`。`project.py data`、`更新并启动.cmd` 和打包自动使用同一数据入口，不需要手动再同步其他JSON。

需要 Python 3.10+、Pillow（原有资源管线）与 openpyxl 3.1.5至3.x；无须安装 Excel。其他机器缺少读表依赖时运行 `python -m pip install -r tools/requirements-tables.txt`。导表不执行公式或访问外部工作簿；刷怪源中的攻击和血量系数必须是粘贴后的实际值。输出携带八份工作簿和schema的SHA-256指纹。

`data/source/defense/reference.json` 保留为冻结的研究来源，被表格接管的定义在加载时整组替换。不要编辑该快照调参。旧hero_roster.json、level_balance.json人工入口已删除。新增机制仍需代码、配置校验和对应验证一起实现。变更的技术依据见 [ADR-0026](adr/0026-defense-xlsx-authoring.md)，验证分级见 [测试方案](TESTING_AND_RELEASE.md)。
