# 当前体验规则与验证

2026-10-14；T8-demo-16；Godot 4.7.1。本轮由用户批准改变原客户端参考规则，较早的四人、三十波及雕像强化报告保留为历史证据。

## 已确认规则

| 项目 | 当前规则 |
|---|---|
| 雕像 | 不攻击；保留生命、受击和归零失败。无英雄目标的怪物向雕像本体移动，攻击框接触雕像身体才能起手，命中帧再次检查距离；底部横线不再作为受击目标。雕像伤害飘字统一显示在雕像上，绘制、技能目标和受击身体共享世界坐标。42 种全队雕像强化不进入运行目录，雕像选择及结算展示路径删除。英雄向雕像方向后撤等自身技能保留。 |
| 职业复活 | 战士、守护、刺客 20 秒；法师、射手、辅助 10 秒。从死亡瞬间按战斗时钟计时，死亡动画包含在倒计时内。暂停/选卡停止时钟，倍速随固定步调度生效；保留英雄复活技能和满血复活，不消耗雕像生命。属性 23 显示完整基础时间。 |
| 出生与归位 | 出生和复活都在雕像正前方；入场/复活技能立即触发一次。近战、远程英雄入场途中按攻击范围优先接敌；攻击、施法及持续施法动作完整结束后，普攻尚未冷却且没有就绪技能出手时，继续向所属阵位行走，即使攻击范围内仍有敌人；冷却结束后恢复攻击，无目标时继续归位。保留原一至四人归位点，增加同排五人点，旧英雄更新目标而不瞬移。 |
| 中下场守位 | 2026-10-16：入场只接战实际攻击框/射程内的敌人，其他时间继续到位。前排按用户红框采用全场固定追击上边界Y=480（720×1440窗口约Y=287），在边界下方全战场宽度内主动接敌；步行追击不得越过上边界，站在边界时仍可攻击已经接触攻击框的敌人；刺杀及追猎允许瞬移到框外，动作结束后逐步走回框内。原阵位前100、横向300的接敌限制删除。阵位后方超过50的漏怪优先处理，回防不受前方横向限制。近身接战的普攻冷却期间站稳；目标逃离时最多步行追至边界，无目标时回到阵位附近，受位移或瞬移到框外时完成当前动作再步行回撤。旧前排横向停留、全局巡逻线及首领收尾越线路径由守位规则替代，远程收尾保留。 |
| 索敌与追击分离 | 普攻按实际攻击框/射程、技能按自身施法和选敌距离索敌，不按敌人Y坐标或红框过滤。删除远程Y=850交战区域限制。前排步行追击限制在Y=480下方，站在边界仍可攻击框外射程内目标，刺杀及追猎允许框外落点并在动作结束后逐步回框；远程不为普通的超普攻射程目标前冲，保留稀疏末波/滞留首领的收尾能力。火球蓄力开始前仍检查射程内合法目标，冷却、控制及完整动作条件保留。 |
| 刺客突进 | 刺杀及追猎按自身技能射程选敌并优先拦截后方漏怪；即使目标在红框外也会瞬移到目标处命中，斩击特效跟随目标；完整动作结束后逐步步行回框，回到框内前不继续主动追击或发起下一次刺杀。保留瞬移、连击、击杀重置及待用追猎加成。射程内没有合法目标时保持就绪，无目标时步行归位。 |
| 阵亡标记 | 死亡动画结束后，十字架留在英雄实际阵亡位置，不随重新编队移动；倒计时结束后，英雄仍从雕像正前方满血复活。 |
| 复活特效 | 满血复活时，在实际复活点播放一次青蓝色光柱与地面光圈，复用召唤动画并放大至1.25倍，持续500毫秒；招募保持原金色。特效只响应复活结果，不控制复活计时。 |
| 招募 | 开局招募第一名；后续每次升级按卡位25%招募、75%强化混抽，允许同轮0至3张招募卡，招募不再绑定波次或等级。上限五名；满编只出强化。召唤物不占英雄名额，死亡不腾出招募位；不保证固定等级满编。 |
| 初版解锁 | 勇者、火法师、德鲁伊、寒冰射手、闪电刺客五名英雄及其词条可选；其他英雄及词条不进入局内候选，图鉴保留已有资料。 |
| 波次与等级 | 当前开放1至5关，每关20波；逐行读取确定怪物ID、数量、触发时间、批次间隔、分布方式和逐行倍率。波次类型为空为普通怪，2为精英，3为首领。局内上限20级，英雄局外等级仍为1。原雕像升级节点由英雄强化取代，宝箱额外强化保留。 |
| UI | 五个底部英雄槽、等级宝石、中文波次、五人贡献列表、属性/技能入口、复活倒计时和五人结算同步适配；结算首领标记按二十波定位。混合卡片分别显示“招募”或“强化”，按单张类型打开资料和提交选择。 |

五英雄当前技能和身份以[新版五英雄](DEFENSE_HERO_ROSTER.md)为准。

规则源为 `data/source/defense/rules.json`（schema 6），编译后的运行目录为 schema 14。原始 `reference.json`、`combat.json` 作为来源证据保留；生成物只通过数据管线重建。逐行刷怪契约见 [ADR-0029](adr/0029-defense-row-spawn-and-five-level-test-catalog.md)。

## 验证与边界

- `test_defense_experience.gd`：合法候选和公开选择接口下验证各级混抽、随机招募时间、满级停止、禁止第六名、雕像池剔除；当前可用英雄的职业计时、暂停、截止前/截止时满血复活、雕像生命保持、出生位置及归位；近战/远程入场途中实际伤害和击杀后的归位；五名英雄召唤及复活后的冷却归位、目标仍存活时完成入场、普攻及技能优先级，以及攻击/施法/持续施法动作不被归位打断。
- `test_defense_combat.gd`：同排五名近战和五名远程站位，死亡保留排内序号、复活从雕像前方出现、重复招募拒绝。原技能、弹体、状态、伤害及AI回归继续执行。
- `test_defense_ai_boundaries.gd`：第5关五种怪物、两种朝向和左右接敌路径，近战接近敌人身体后确实进入攻击，避免追逐偏离身体的出招点而抖动。
- `test_defense_guard.gd`：勇者/刺客入场不偏离路线、带存活目标实际到位、全宽索敌与后方漏怪优先、持续近身攻击和冷却站稳、追击停在红框边界、无目标时步行回撤、动作锁定及受位移后逐步回撤；边界外射程内目标仍可被普攻、刺杀和真实追猎命中，框外落点、完整动作、逐步回框及斩击特效分别验证。
- `test_defense_ranged_range.gd`：火法/德鲁伊/寒冰射手在旧交战线之外实际普攻命中，火球术与多重射击独立射程命中；超射程不前冲、不消耗冷却，缓存目标离开射程立即释放，范围内仍遵守冷却。
- `test_defense_statue.gd`：两侧底线不能隔空攻击、接近雕像后真实伤害、命中帧被移开时不扣血，技能目标与飘字位置一致。
- `test_defense_experience_ui.gd`：通过真实鼠标输入检查五个头像、技能气泡开闭、第五槽倒计时、贡献列表、等级/波次显示、五人结算的边界和全部 i 入口。
- Python 数据检查覆盖无效规则、职业、出生点、五人站位、首领引用，并确认编译不修改来源对象。
- 固定招募阶段的历史采集 `validation/defense/experience/capture.log`：种子6、合法候选和刷新、基础雕像生命3900，真实领域战斗完成二十波，击败三位首领、269个非首领单位，招募五人，经历6次英雄死亡，最终胜利。没有增加雕像生命、英雄属性或直接杀敌来取得通关。模拟战斗用时264224毫秒；不是当前混抽规则的通关记录，也不是实机人工操作耗时或全部五十关通关证明。采集脚本已同步单张类型以便后续使用。
- `capture.log` 保留对局历史、队伍、结果和原生五槽输入检查。`five_heroes_*`、`contribution_*`、`revival_*`、`result_*` 为同一真实对局的960×1920、720×1440、540×1080原生截图。三档矩阵检查五槽、贡献背景、倒计时与结算；不代表移动平台导出验收。
