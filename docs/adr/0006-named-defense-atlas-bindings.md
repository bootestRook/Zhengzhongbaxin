# ADR-0006：界面只绑定有名称的图集资源

- 状态：采用
- 日期：2026-10-14
- 范围：defense 美术导入、数据管线、界面表现

## 原因

图集更新后页顺序、切图位置和页面尺寸发生变化，主页保存的 AtlasTexture 坐标指向了其他素材。其他界面还有依赖旧精灵尺寸的内部裁切；源索引中的三个重名条目也曾依靠导入顺序覆盖。

## 决定

- 所有界面通过 DefenseAtlas 按名称查当前索引。固定 TextureRect 只保存 resource_key；页路径、切图位置和光纹 UV 都在配置时解析。
- 头像和六个补充图标使用同一 sprites/pages 索引，导入工具总是重新登记其名称。来源、裁切和透明处理仍由已有参考图导出流程负责。
- 纸框内部、按钮表面等九个命名子区域由数据管线按当前精灵的相对范围生成。沿用既有图集数据结构，界面不再传入像素裁切。
- common:talentPointReward、common:bg3、map:circular 的同名素材使用名称加源 item_id 区分，即使其中一个删除也保留剩余素材的限定名称。删除含糊的旧名字，不增加别名；新的名称冲突拒绝导入。
- 数据检查拒绝界面中直接引用图片页、静态 AtlasTexture 或直接访问页数组，拒绝缺失名称、无效页及越界区域。可用英雄、属性、技能和前 50 关的动态画像名称由 Godot 测试覆盖。
- 沿用 provenance 的 runtime_sha256 验证图集与索引是同一批导出。直接替换图片而未重新导入索引时，生成资料和启动检查失败，禁止用刷新资产清单掩盖图集变化。

没有新增数据格式、运行时全局状态、依赖、保存或随机契约。导入图集时保留独立音频索引，不重写玩法资料。

## 取舍

逐次重建场景仍会遗漏其他界面；原样保留像素裁切会再次依赖旧尺寸。命名子区域只增加索引项，不增加图集像素或运行时重采样。相对范围可跟随素材等比换尺寸；如果素材内容轮廓变化，仍需要美术验收相应子区域。

## 验证

全量项目检查包含名称、位置和尺寸更新的失败测试。原生回归覆盖 23 种界面状态及 540×1080、720×1440、960×1920：反转全部页面，给实际图像增加边距，同时移动每个精灵的索引区域，逐组比较重排前后的渲染。允许 GPU UV 运算的微小舍入差：RGB 平均误差不大于 0.05，超过 2 色阶的像素不超过 0.01%。资源文件保持原状。

重新评估条件：资源命名或源图内部结构变更。图集打包位置和页数变化不要求修改界面场景。
