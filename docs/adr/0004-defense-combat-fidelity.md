# ADR-0004：战斗坐标、动作元数据与空间规则

状态：采用。日期：2026-10-13。

当前战斗把世界压缩到画布、等距分配英雄出生点，并在 AI 决策时立即结算普攻。当前客户端资源及动作状态机证明这些路径与参考不一致。

在 defense 内增加独立的战斗元数据 `data/source/defense/combat.json`，记录已核实的世界边界、两排锚点、角色动作帧时间/有效帧、攻击点、显示锚点和弹体碰撞元数据。该文件由明确的参考导入入口生成，日常 data 检查读取本地冻结版本；不在运行时读取外部源码。更新 defense 生成目录的 schema 至 2，删除旧 schema 接受路径。

空间查询、阻挡归属和动作推进由领域对象持有；表现只读取动作时间、朝向、锚点和弹体旋转。伤害发生在领域有效帧或弹体命中，动画节点不决定伤害。所有新增玩法随机继续使用现有 defense 命名流；不用表现随机驱动规则。不增加 Autoload、依赖或跨 Feature 调用。

世界为 1600×1600，活动横界为 350–1250，城墙 Y 为 1460。画布横坐标为世界 X−320，纵坐标通过城墙画面基线 1563 对齐。每排 1–4 人锚点按本排入场序号读取；已有英雄只更新 home 并通过行动回位。出生排由基础远程弹道确定，不随临时射程增益更改。

寻路使用目标引擎的 AStarGrid2D，在 50 像素网格上覆写源客户端的单位步长和拥挤评分。脚部物理半径、身体受击框和攻击框分开保存。弹体创建、移动轨迹、碰撞形状和伤害结算分开持有；按资源尺寸缩放碰撞框，不把所有特效解释成同一个圆。

死亡分为死亡动作/尸体阶段和墓碑复活阶段。复活基准从冻结配置读取，英雄属性 23 为额外秒数。死亡前即时治疗可以阻止死亡；死亡后技能有明确的施法标记，能够在死亡状态下完成自身弹体和后续链，不开放一般死亡单位的施法权限。

验收：站位所有人数、重复招募、死亡期间重排；有效帧前无伤害、远程飞行与目标失效；索敌筛选/排序/随机候选数；阻挡释放；Boss 超前波数和压力计时；不同执行器及链事件；纯领域回放、实际原生窗口和完整 project.py check。未闭合的参考资料与逐英雄动态核验必须单独列出，不将通过自动测试写成全面 1:1 验收。

2026-10-14 补充：同一元数据契约补齐角色 buff 区域、动作附层与 buffData 的效果尺寸/枢轴。静态资源参数继续由明确导入入口生成；快照只提供按这些参数计算的表现提示。施法动作推进单独持有，不再用索敌规则数量决定发射数量；绘制使用领域弹体的逻辑缩放与资源显示缩放。没有新增 Save、RNG、Autoload 或跨 Feature 契约。

2026-10-14 再核对：将误用的单一警戒线拆为当前客户端实际使用的入场警戒线、通常索敌线、退线索敌线和后方威胁线。它们从 battleBar3 的四个 heroPoint 与 function_price 的 line1–4 计算并冻结；删除未使用的 back_y 字段。退线状态由 defense 会话持有，索敌与归位由领域决定。怪物成长同时读取关卡和章节修正，保留波次与精英成长。新增字段只扩展既有 combat 元数据，不增加 Save/RNG/全局契约或第三方运行依赖。
