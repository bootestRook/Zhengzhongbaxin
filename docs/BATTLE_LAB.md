# 战斗测试场

双击根目录 `启动战斗测试场.cmd`，或运行 `python -X utf8 tools/battle_lab.py run`。依赖与普通工程一致；默认加载火球不死靶配置并暂停。默认窗口 1360×1000，最小 720×640。顶部“工具面板”可收起侧栏，放大战场。

场景 `scenes/defense_lab.tscn` 实例化原 `scenes/main.tscn`，沿用角色、战场、HUD、动画、弹体、音频及正式战斗规则。测试控制保存在 Defense 内部的 `domain/lab`，人工和自动化都调用 `battle_lab.gd`，操作后从真实状态读回。普通入口不展示测试工具；Windows/Web 导出与发布清单排除测试模块。

## 人工操作

| 位置 | 操作 |
|---|---|
| 顶部 | 暂停/继续；16ms 单步；推进1.6秒；推进至下次起手、实际伤害或死亡（最多20秒）；0.25/0.5/1/2/3倍观察；重开；判定范围 |
| 单位 | 召唤当前开放的指定英雄；按名称/编号搜索怪物，普通/精英/首领；每批1–300个，单点、横排、纵排、环形、网格、随机；指定坐标或点击战场放置；清除选中、全部怪物或全部单位 |
| 词条 | 显示所选英雄的原始词条说明、次数及前置；添加、移除、清空强化；可自动补齐前置；合法模式遵守前置与次数，自由模式允许越过前置并设1–20次，始终醒目标记 |
| 属性 | 基础属性、当前生命比例、护盾；单个/全部怪物/同模板批量调整；移动/普攻/技能分别开关；冷却就绪、残血至1、人工击杀、英雄测试复活、状态及持续时间、雕像生命 |
| 状态 | 当前目标、生命/护盾、击杀、伤害/治疗/承伤、技能实例参数与冷却、Buff来源/层数/剩余时间、属性基础值与聚合结果 |
| 记录 | 起手、普攻、施放、伤害、治疗、状态增删、死亡及人工操作；按文本或选中单位筛选；记录最近2000条并显示丢弃数与逻辑步耗时 |
| 用例 | 八个预设；固定随机种子、关卡、波次；自动刷怪、完整关卡流程、死亡后补怪；保存/加载配置、保存/重放操作、导出结果与事件 |

点击战场中的单位或上方单位列表选中。判定叠层显示实际受击框、攻击框、弹体形状、选中目标连线与范围；圈内并不保证发动，仍须满足冷却、控制、目标类型和动作条件。无名称的怪物以模板编号/资源标识显示，不编造名字。

## 不死靶与击杀效果

| 模式/操作 | 语义与适用场景 |
|---|---|
| 正常生命 | 真实扣血、死亡、复活与击杀；用于低血量、致死、斩杀、击杀后触发 |
| 不死靶 | 经过正式命中、暴击、减伤、护盾及受击链；扣血事务中补满生命，阻止死亡/斩杀；统计完整结算伤害，即使伤害高于最大生命。适合连续输出、弹体与受击观察，不用于低血量/致死判定 |
| 无敌靶 | 拒绝伤害，不增加伤害统计；不等同于免疫所有状态与控制 |
| 残血至1 | 切回正常生命并设1点血。现有护盾、闪避、免疫、保命效果仍有效，可按需清除；随后由真实普攻/技能完成击杀 |
| 人工击杀 | 走正式死亡接口，可指定击杀归属；验证死亡和通用击杀触发。保命机制仍可能阻止死亡。不能代替刺客追猎等技能专属击杀测试 |
| 清除 | 从战场和配置移除单位、所属召唤物及关联状态/弹体/延迟行为；不触发死亡、击杀、掉落；清怪会取消相关补怪 |

例如测试刺客追猎：加载“刺客：真实刺杀击杀后追猎”，使用正常生命怪物，推进到死亡，再查看刺客技能的 `hunt_ready` 与死亡来源。测试连续火球：加载火球预设，不死靶持续保留，单步检查起手、飞行、命中和实际伤害。

“静止靶”关闭移动、普攻和技能；要测试怪物受击技能，请开启技能。已经产生的弹体/状态仍按正式生命周期运行；需要完全清洁的场景时使用重开。英雄最多五名且不能重复同模板，配置最多500个单位。

## 重开、保存与复现

- 属性修改写入实例基础值，现有词条和状态仍参与最终值；旁边显示实际聚合结果。
- 增删词条、应用环境/构筑模式、加载配置均重建整个战场并暂停，清掉旧状态、弹体与计时。初始技能保留；此举避免“反向撤销词条”留下残余。
- “保存配置”记录单位、属性覆盖、词条、位置、生存/行为设置及环境，不是任意时刻的存档。临时护盾、Buff、残血按钮等操作要保存为重放才能复现。
- “保存重放”从本次配置起点记录选择、修改和固定16ms步进；重新配置会建立新起点。记录最多10000个操作，连续步进合并；截断记录拒绝重放。单条合并步进重放上限100万步。
- UI重放核对当前源数据与代码/场景指纹；代码或数据变化后使用“加载配置”重新跑验证。默认环境隔离选卡、奖励、胜负；开启“完整关卡流程”后使用真实选卡与奖励界面，结算确认返回测试配置。
- 配置仅保存在用户选择的文件；退出后重新打开默认预设。测试文档格式版本1，无旧格式迁移。协议与边界见 [ADR-0027](adr/0027-defense-battle-laboratory.md)。

## 自动化与修改技能后的工作流

```powershell
python -X utf8 tools/battle_lab.py test --suite controls
python -X utf8 tools/battle_lab.py test --suite cases
python -X utf8 tools/battle_lab.py test --suite heroes
python -X utf8 tools/battle_lab.py test --suite ui --capture
python -X utf8 tools/battle_lab.py test --suite coverage
python -X utf8 tools/battle_lab.py test --suite profile
python -X utf8 tools/battle_lab.py case --case tests/lab_cases/01_fire.json
```

先在同一测试场搭建复现，保存配置/操作。修改源表后先运行 `python -X utf8 tools/project.py data`；修改代码或生成数据后关闭并重新打开测试场，运行中的实例不自动热载入。修技能后跑直接相关用例，检查独立预期，再按 [测试方案](TESTING_AND_RELEASE.md) 增加必要关联回归。人工观察与自动断言使用同一个实例、命令和固定步进接口；并不通过单独模拟伤害来替代真实战斗。

| 套件 | 实际覆盖 |
|---|---|
| controls | 输入拒绝与事务性、清除/击杀差异、属性读回、不死/无敌、词条合法性、重放、补怪/复活、完整流程失败结算 |
| cases | 火球命中不死靶、勇者圣盾受击、德鲁伊治疗护盾、寒冰命中、刺客追猎、刺鼠受击技能、刺客精英最终乘区、寒冰连击0.3秒间隔；各自有明确伤害/血量/状态/事件预期 |
| heroes | 复用五英雄词条、最终乘区、技能激活与弹体的既有规则回归 |
| ui | 真实鼠标输入和权威状态读回；1360×1000、960×720、720×1080；`--capture` 输出18张原生截图 |
| coverage | 当前201个怪物模板和47条初始/强化词条的配置与运行烟测，报告实际观察到的施放；不证明每个机制正确，也不覆盖所有组合 |
| profile | 固定种子100/300怪物的180步逻辑/快照耗时、重复重开及清理；不含渲染，不能当成帧率保证 |

结果位于 `validation/battle_lab/<suite>.json`，包含断言数、失败、耗时与指纹；同名 `.log` 保留引擎输出。退出码、错误标记、零断言和缺失报告均会失败，旧报告不会被当成本次结果。`case` 支持外部用例，`--output` 可指定报告。内置用例文件位于 `tests/lab_cases/`，复制相近文件后修改 `config`、顺序 `commands` 和独立 `checks`；无断言用例不能通过。支持单位字段/技能字段、世界字段、事件数量的 `eq/gte/lte/near` 检查。

完整工程检查已接入 controls、内置 cases 和真实 UI 输入；重型目录覆盖/压力仍使用显式入口。自动断言、烟测、截图可读性、人工动态特效/音频观感分别判定；截图通过不表示所有技能表现都已人工验收。
